# 规则放哪里：一类事一个家（2026-11）

背景见 `docs/diagnosis/2026-11-diagnosis.md`。诊断发现规则按“哪里出问题就在哪里补一条”堆积，分散在八层，同一条写在好几处，最要紧的红线反而没有硬约束，钩子坏了也没人知道。本文定下每类规则的唯一归属，新增规则先按下表找家。

## 一、归属表

| 这类事 | 放在哪 | 靠什么执行 |
|---|---|---|
| 红线：强制推送主分支、对生产环境做写操作 | 插件钩子 `guard/redline.py`；生产主机清单在本机 `~/.claude/redlines.json`（私有，不进仓库） | 钩子拦截；用户在对话里同意后放行并记录 |
| 其余红线：动真钱、删真实数据、用共享环境真实资源 | 个人全局规则 | 自觉（还没有能机器判断的特征，有了再进钩子） |
| 危险命令：按名字批量杀进程 | 插件钩子 `guard/block-broad-kill.py` | 钩子拦截 |
| 交互形式：中文回复、不出选项卡 | 个人钩子（`~/.claude/hooks/`，本机私有版本管理） | 钩子检查 |
| 工作偏好：讨论和执行两种节奏、开工对齐、交付说清 | 个人全局规则 `~/.claude/CLAUDE.md`，一份，控制在 200 行内 | 自觉；能落成模板必填栏或钩子的落过去 |
| 主脑流程：派活、验收、合入、台账、卡片 | 本仓库插件的技能、模板、输出风格 | 技能按需载入；回报格式、卡片格式由插件钩子检查 |
| 项目进度的可见性 | 各项目卡片事件记录 + 本仓库插件的卡片命令和看板；会话实况由插件钩子写在本机 | 主脑只用卡片命令记事，命令检查规则；手改卡片文件由钩子拦下 |
| 技术踩坑（和某类文件相关） | `~/.claude/rules/pitfalls/`，用 `paths` 限定 | 碰到相关文件时自动载入 |
| 技术踩坑（和文件无关） | `~/.claude/pitfalls/` | 全局规则里一句指路 |
| 项目事实与业务约束 | 项目根目录一份 CLAUDE.md；项目记忆只放事实 | 自动载入；记忆索引只载入前 200 行，超了要瘦身 |
| 代码与文档索引 | gitnexus（代码引用关系）、graphify（文档和文件内容），由工具注入到项目规则 | 工具自己维护 |
| 钩子是否在工作 | 所有自有钩子经 `scripts/hook-run.py` 运行，拦截和出错写进 `~/.claude/logs/hooks.log`；例外是会话实况钩子（每次工具调用都跑，用 sh 直写，失败时看板显示“不在线”） | 周复盘读这份记录 |

## 二、原则

1. **一类事只放一处**，其他地方只引用、不复述。
2. **约束强度和重要性对齐**：越要紧的越用硬机制。能机器判断的落到钩子或权限，判断不了的（比如需求理解对不对）留给开工对齐那道人工关，不硬凑。
3. **常驻篇幅有预算**：常驻规则每加一条就删一条，或者改成按需载入（技能、带 `paths` 的规则）。
4. **第三方组件要有主人**：装进来的插件、命令、子代理，用证据决定去留。没人用的移走，冲突的停用。
5. **闸要有记录**：自有钩子的拦截和出错都留痕，“规则有没有效”看记录，不靠翻会话记录。
