# 跨项目看板设计（2026-11）

状态：设计稿，待用户定第七节的三项后实施。
演示版：桌面版改造，已在一个会话里跑通；数据是从台账手抄的演示卡片。

## 一、要解决的问题

用户同时推进多个项目，而且是每个项目唯一的推动者，一件事被忽视就会长期搁置。他每天都会主动去看，但看的时候会陷进混乱的信息池。原因是信息没有分层：项目、事项、会话、遗留小项、讨论记录都堆在同一层；各项目主脑又用各自的格式写长文；每看一次，用户都要自己拼出“这是哪个项目的哪件事、现在什么状态、轮到谁动”。

清理会话解决不了问题：很多会话是刻意保留的，而且清掉还会再长出来。要改的是用户和主脑之间交接信息的方式。

## 二、定位

1. **只做提醒和查看，不做输入。** 看板上不写批注、不改状态、不发指令。用户要动作时，点卡片直接跳到对应会话，在那里说话。
2. **不推送。** 用户作息规律，会自己来看。提醒靠打开看板时的醒目程度：轮到你的件数、等太久标红、主脑太久没动标黄。
3. **看板是主脑写给用户的唯一交接面。** 主脑在对话里的长篇汇报，改成更新卡片，再加一句“已更新卡片 X”。

## 三、信息模型

### 1. 一张卡 = 一件要交付的事

会话、分支、提交、讨论记录都挂在卡下面，不单独上板。用户刻意保留的会话，通过所属的卡进入。

### 2. 按“轮到谁动”分列

| 列 | 意思 | 平时是否显示 |
|---|---|---|
| 等你 | 要你拍板，或要你本人动手（登录、采购、发邮件） | 显示，排第一 |
| 待你验收 | 做完了，等你亲眼看一下 | 显示 |
| 主脑在做 | 主脑或分支会话在做，不用你管 | 显示 |
| 等外部 | 球在合作方、律所、同事手里 | 显示 |
| 冻结 | 你说过先放着 | 收起，只显示件数 |
| 已完成 | 7 天内完成的 | 收起；满 7 天主脑删卡，历史看周流水 |
| 库存 | 台账队列里的遗留小项、尚未排期的想法 | 不上板，只在项目行显示件数 |

### 3. 卡片字段

用户看到的只有前七项。主脑自用的技术细节（分支、提交、验收要点）放在“详情”里，看板不显示。

| 字段 | 写法 | 必填 |
|---|---|---|
| 标题 | 20 字以内，业务语言 | 是 |
| 现状 | 一句话，40 字以内 | 是 |
| 要你做 | 一个动作，动词开头，40 字以内 | 等你、待你验收两列必填 |
| 下一步 | 你做完之后会发生什么 | 否 |
| 进入本列日期 | 每次换列时更新，用来算“等了几天” | 是 |
| 预计回球日期 | 等外部、主脑在做的预计日期，过期就标黄 | 等外部必填 |
| 挂着的会话 | 会话名加会话编号，点击跳转 | 否；没有时跳到本项目主脑会话 |
| 主脑确认日期 | 主脑最后一次核对这张卡的日期 | 是 |
| 详情 | 待拍板的完整决策栏（选项、推荐、代价、能否撤回），以及主脑自用的技术栏 | 否 |

### 4. 醒目规则

| 情况 | 显示 |
|---|---|
| 等你、待你验收两列里，等了 7 天及以上 | 天数标红 |
| 主脑在做的卡，主脑 3 天没确认 | 标黄“主脑 3 天没动” |
| 等外部的卡，过了预计回球日期 | 标黄“对方逾期 N 天” |
| 整个项目的卡片文件 5 天没更新 | 项目行标红“主脑 5 天没动”：用来发现被整个遗忘的项目 |
| 卡片文件格式不合格 | 顶部红条，写明是哪个项目 |

阈值先用这几个数，用一周后再调。

## 四、数据放在哪里

每个项目一份卡片文件，放在台账旁边：`<项目文档目录>/brain/cards.json`。只有本项目主脑写它，随台账一起提交。

| 方案 | 结论 |
|---|---|
| 每个项目一份文件，放在台账旁（采用） | 一个文件只有一个写入者，不会互相覆盖；跟着项目仓库有版本历史 |
| 所有项目写同一份中央文件 | 多个主脑同时写会互相覆盖；不采用 |
| 看板直接解析台账 | 各项目台账格式不统一，看板会跟着乱；不采用 |

看板通过本机登记表 `~/.claude/board/projects.json` 知道去哪里读。登记表每项写项目显示名和主仓目录。登记表只在本机，不进任何仓库。

卡片文件顶层另记本项目当前主脑的会话名和编号，供没挂会话的卡跳转。主脑开局登记自己时一并写入。

## 五、和台账的关系

卡片取代台账里的三节：在飞、待用户拍板、队列（队列转成“库存”列）。台账只保留规则、环境与待清理两节；决定、周流水、交接三份文件不变。这样同一件事只记一处，看板显示的就是主脑的工作底稿。

这一条要用户定，见第七节第 1 项。

## 六、实现

### 1. 看板改造

- 桌面版改造，挂在对话旁边。源码放进本仓库 `board/mod/`，不含任何项目数据。
- 安装方式：把改造目录写进全局设置的插件目录变量，所有会话都能用 `/board` 打开。用户固定一个名为“看板”的会话，在里面常开。
- 读取：登记表加上各项目的卡片文件，每 5 秒检查一次文件有没有变化。
- 交互只有三种：
  - 点卡片，展开或收起；
  - 筛选项目，或切到“只看轮到我”；
  - 点“打开会话”，跳到对应会话。

### 2. 格式检查（强制，不靠主脑自觉）

- 检查脚本：放在本仓库 `board/check-cards.py`，检查列名、必填项、字数、日期格式。
- 主脑写卡片文件后由钩子自动运行检查；不合格就把错误退回给主脑，要求它改。
- 看板读到不合格的文件，显示红条，不静默跳过。

### 3. 主脑技能改动

- 台账模板删掉在飞、待拍板、队列三节，改成卡片文件模板。
- 原来“每个动作后改台账”的触发点，改成“改卡片”。
- 给用户的回复缩短：先写“已更新卡片 X”，后面只接需要用户此刻在对话里回答的问题。
- 迁移步骤写进技能：主脑下次被唤醒时，自己把台账三节转成卡片，交给检查脚本验证，然后提交。

### 4. 已核实与待核实

| 能力 | 状态 |
|---|---|
| 桌面版面板：多号字体、按钮、下拉框、自适应宽度 | 实测（演示版） |
| 点击卡片展开 | 实测（用户点击，记录文件里有对应记录） |
| 读本机任意文件、定时刷新 | 实测（演示版） |
| 点链接跳转会话（链接格式取自会话管理工具返回的会话地址） | 未核实：接口说明写着远程界面只认网址，桌面版可能只把它画成普通文字。做不到时，退回为显示会话标题，到侧边栏找 |
| 面板在固定的“看板”会话里能否常开、重启后能否自动恢复 | 未核实 |

## 七、要用户定的三项

### 1. 卡片和台账的关系

核心需求：同一件事只有一个地方记，看板显示的就是主脑真实的工作状态。

| 选项 | 说明 |
|---|---|
| 1（推荐）卡片取代台账三节 | 只有一份记录；要改主脑技能，迁移由主脑自己做 |
| 2 卡片从台账自动生成，看板只读 | 主脑技能改动小；但台账格式乱，生成出来的卡片也乱 |
| 3 折中：在飞和待拍板转成卡片，队列留在台账 | 改动小一些；库存件数要另外统计 |

- 不按推荐的代价：选 2，看板质量取决于四个台账的格式，问题没解决。
- 能否撤回：能。卡片文件可以再转回台账，有版本历史。

### 2. 上线节奏

核心需求：看板的价值在于跨项目总览，只有一个项目上板，测不出“信息池”问题有没有解决。

| 选项 | 说明 |
|---|---|
| 1（推荐）四个已有主脑的项目同时迁移 | 一次见到全貌；格式问题由检查脚本兜底 |
| 2 先一个项目跑两天，再推广 | 稳一些；头两天看板上只有一个项目 |
| 3 先迁两个当前最活跃的项目 | 折中 |

- 能否撤回：能。

### 3. 没有主脑的项目

现在大约有 7 个项目只有会话、没有台账，它们不会出现在看板上。

| 选项 | 说明 |
|---|---|
| 1（推荐）先不管 | 等哪个项目重新动起来，开主脑时自然上板 |
| 2 每个项目手写一张“项目还活着吗”的卡 | 提醒你它们存在；要人维护 |
| 3 看板项目行列出“有会话、没上板”的项目 | 需要“驾驶舱”会话定期扫会话列表，写进登记表 |

- 能否撤回：能。

## 八、实施顺序

1. 卡片格式和检查脚本，附测试。
2. 看板改造正式版：多项目读取、项目行、醒目规则、展开显示决策详情、跳转链接；安装脚本加上看板。
3. 改主脑技能和台账模板。
4. 按第七节第 2 项的节奏迁移项目。
5. 用一周后复盘：
   - 主脑周流水里的注意力指标；
   - 用户主观感受：打开看板后，能不能在一分钟内知道今天该做什么。

## 九、和既有计划的关系

诊断文档第三批的“注意力收件箱模组”，由本看板取代：待授权、待决策、待验收，就是这里的“等你”和“待你验收”两列。
