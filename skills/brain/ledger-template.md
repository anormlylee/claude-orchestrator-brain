# 台账模板

放在项目文档目录下的 `brain/` 里：多仓项目放文档/契约仓，单仓项目放 `docs/brain/`。项目已经有同类文件就迁进这个结构，旧文件删掉，git 里有历史。

```
brain/
  cards.json       卡片：每件正式事项一张，看板读它（增删改）
  ledger.md        规则、遗留小项、环境（增删改）
  decisions.md     仍然有效的决定（增删改）
  handoff.md       下周开工第一屏（每周整篇覆盖）
  log/2026-W39.md  周流水（只追加本周）
  inbox/           讨论会话交回的文档（主脑处理完就删）
```

## cards.json

格式见 claude-orchestrator-brain 仓库的 `board/cards-format.md`，要点见 SKILL.md「卡片」。新项目从这里起步：

```json
{
  "project": "<项目名>",
  "stage": null,
  "stageGoal": null,
  "brain": { "name": "<主脑会话名>", "id": "<主脑会话编号 local_…>" },
  "leftovers": 0,
  "cards": []
}
```

## ledger.md

```markdown
# 台账（主脑维护，反映"现在"）

在飞、待拍板、队列都在同目录的 cards.json 里，这里只放规则、遗留小项和环境。

## 0. 规则
当前主脑会话：<会话名>（<YYYY>-W<ww> 起；每次换主脑时更新）
交回目录：<讨论会话交回文档的目录，比如 docs/gap-reports/ 或 brain/inbox/>

以上两行的开头文字固定不变，讨论会话靠 grep 这两个前缀找到台账和交回目录。

1. 派活权、验收权只在主脑。讨论会话只把结论落成文档（<gap-report 目录> 或 `inbox/`），直接提交到 main 后通知主脑。
2. WIP：<仓> 同时在飞代码分支 ≤ <N> 条。
3. 串行合入；每合一条，其余在飞分支 rebase 并重跑测试。
4. 联合验收：在合并后的 main 上跑全量。
5. 契约先行：<契约/ADR 所在仓> 先合。
6. 合入权限：<ff 合入并直接 push main | 每次合入先问用户>。
7. 测试口径：<全仓命令>；<集成命令>；真依赖地址 <...>。

## 1. 遗留小项（零碎的小事，不上卡；件数同步到 cards.json 的 leftovers；挑出来排期时转成待办卡并从这里删掉）
- <一句话> —— 来源 <文档/会话>

## 2. 环境与待清理
- 待归档会话：<会话名>（<原因>；等它空闲后归档）
```

## log/<YYYY>-W<ww>.md

```markdown
# <YYYY>-W<ww> 流水
- <日期> **<动作>**（<仓 commit>）：<内容>。验收：<全量结果>；探针 <x 红 / y 存活→处理>。问用户 <N> 次。
- <日期> **发现停滞** <会话名>：停在 <提问 / 报错 / 权限>，<停下时间> → <发现时间>，未发现 <分钟>。
```

## handoff.md

```markdown
# 主脑交接（<YYYY>-W<ww> → 下周）

| 卡片编号 | 分支 / 会话编号 | 列 | 验收要点 |
## 3. 本周注意力指标
- 打扰次数：共 <N> 次，验收通过 <M> 项，平均每项 <N/M> 次
- 停滞未发现时长：共 <分钟>，最长一次 <分钟>（<会话名>）
- 无干预连续通过：最长 <K> 项
## 4. 下周优先级
## 5. 本周踩坑（已写进记忆的注明）
## 6. 新会话开场白（直接粘贴）
> /brain 然后：① …… ② ……
```
